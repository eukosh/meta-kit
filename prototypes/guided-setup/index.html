Guided setup for skit PROTOTYPE · throwaway

Question: how should skit auth login walk someone from nothing to working Instagram, Facebook Pages and Threads access, and what does an agent see through the MCP setup_guide tool at each point? The proposal under test: no progress file. Every run works out what is missing from the files on disk and what Meta reports, and a step skit can't check (a dashboard permission, the Threads tester invite) is shown until the sign-in it gates succeeds.

Open questions to react to
  1. Bare skit auth login starts with check marks for what is connected, then asks what to do: connect what's missing (the default) or add another account to a connected platform.
  2. Browser sign-in is the default; the system-user token is --token only. Should the prompt offer the choice instead, given Page tokens from the browser sign-in never expire either?
  3. Threads: paste the localhost address (shown here) versus a local https listener with a self-signed certificate (a browser warning instead of a paste).
  4. Steps skit can't check are re-shown on every run until a login proves them. Too repetitive, or the right trade for having no progress file?
  5. Missing permissions don't block: sign-in succeeds, skit names the commands that won't work, and offers to sign in again or skip.
  6. setup_guide lists the dashboard steps, but credentials and sign-ins only happen in a terminal. An agent can walk the user through Meta's dashboard, then hands over to skit auth login, which shows those steps again.
  7. Linking Instagram after sign-in is re-checked with the stored token (no second browser trip). Live check needed: does a token granted "all current and future" see a newly linked account?
