Guided setup for skit PROTOTYPE · throwaway

Question: how should skit auth login walk someone from nothing to working Instagram, Facebook Pages and Threads access, and what does an agent see through the MCP setup_guide tool at each point? There is no progress file: every run works out what is missing from the saved files and from what Meta reports, and a step skit can't check (a dashboard permission, a redirect, the Threads tester invite) is shown until the sign-in it gates succeeds.

What the review settled
  1. Every skit auth login opens with check marks per platform, checked live with Meta, then offers to connect what's missing (the default) or add another account.
  2. First run is one dashboard pass: the app, every permission, both redirects and the Threads tester, then the credentials. The two sign-ins follow back to back.
  3. Browser sign-in is the default; --token takes a system-user or Threads token; --no-browser prints links and takes the address back as a paste, for SSH.
  4. Missing permissions never block. skit names what won't work; skipping is remembered in the login, so it stops asking.
  5. Adding a Page or Instagram account re-discovers with the stored token first and opens the browser only if nothing new turns up.
  6. Credentials and sign-ins happen only in a terminal; setup_guide lists the dashboard steps for an agent to walk through.
  7. Live check still open: whether a token granted "All current and future" sees a newly linked Instagram account.
